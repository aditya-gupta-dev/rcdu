# Decision log

- Preserve ncdu 2.9.2 under `reference/ncdu-2.9.2/`, including notices, license, source, build recipe and manual. GUIDE links point to this snapshot. Installed ncdu and a controlled Zig 0.15.2 ReleaseFast source build are kept under ignored `target/baseline/` paths; artifact hashes are in measurement files.
- Linux only, one crate. Filesystem/syscall/account/terminal operations stay in `src/os/linux.rs`; serialization, model, browser and mutation policy are separate. Unsupported operating systems fail at compilation. Linux architectures other than the tested x86_64 GNU target require validation before distribution.
- Preserve one scan worker by default and `-t 0` automatic selection. Build jobs use a separate affinity/cgroup-aware half-CPU limit via `scripts/cargo`; no fixed machine-specific job count. `scripts/zig` additionally constrains backend affinity for reference builds. The reference Makefile's historical `-j8` recipe is preserved but is not used by the active build workflow.
- Safe Linux wrappers around libc getdents64/fstatat/openat are the default. Optional statx requests/checks all basic-stat masks and falls back on ENOSYS/EINVAL/EPERM or insufficient masks, with fault-injected differential tests. Permission/I/O errors are not silently retried as absence. The current dynamically linked build needs glibc 2.28+ for libc statx; older-libc/raw-syscall distribution is not claimed.
- Dense observations initially used 32-byte entries. Measurement on 1,394,617 synthetic files showed excessive RSS. Entries now occupy 24 bytes; parent IDs live in ordered runs because consecutive observations usually share a parent. Directory and link records are sparse ordered side tables searched by ID. Worst-case parent alternation adds one 8-byte run per record, comparable to the former record size. No full path or individual name allocation is stored per ordinary file. The before/after evidence retains both executables' hashes and all raw runs. Parent lookup and side lookup trade CPU work for lower memory and are checked against the prior layout.
- Ordinary totals and reachable hardlink discovery share one postorder pass. A separate all-entry pending stack was removed, reducing wide-directory transient memory and checking cancellation within wide reductions. Hardlink groups still reduce identities across every ancestor; zero or inconsistent nlink uses the globally observed group count. Direct streaming binary scans retain per-directory inode maps and use local observed counts for unknown nlink, as the reference does; live files with valid nlink and memory conversion have the complete-tree semantics tested.
- Keep JSON byte-preserving and streaming rather than using a UTF-8 DOM. Single-worker scans stream; multiple-worker exports stage observations with unused totals disabled. Preserve the early/late enumeration-error limitation explicitly. Binary export uses per-worker encoding/compression buffers and locks only output publication/sibling linkage. Reader/writers share the 64 MiB index limit; checked packing limits and cache/resource bounds reject malformed inputs. Binary stdin explicitly requires a seekable file. Zstandard JSON decoding caps window distance at 128 MiB.
- Imported exclusion/error classification is independent of JSON field order: later inode/nlink fields cannot overwrite special kinds. Unsafe child names and cycle/resource violations are rejected. Readonly root text may be arbitrary, but filesystem actions require an absolute root without dot/dotdot components. These are deliberate validation corrections rather than claims of accepting every malformed reference export.
- Preserve saturation and exact allocated/apparent separation. Integer `u128` formatting fixes reference formatter overflow at very large values. Display escapes raw controls, invalid UTF-8 and bidi controls, while names remain bytes for identity. Grapheme-aware shortening preserves combining sequences and ZWJ clusters; display appearance is intentionally different from locale-dependent ncurses rendering.
- Terminal ownership uses `/dev/tty`, termios and ANSI, with restoration on normal/error/signal/panic exits. The panic hook's duplicate fd is released and the previous hook restored on normal session shutdown. While unwinding, Rust forbids changing panic hooks; the installed hook has already restored the tty and is retained until process exit. Off/dark/dark-bg themes preserve defaults but are not pixel-identical ncurses layouts.
- Refresh builds a replacement transactionally and compacts reachable observations, reclaiming previous generations; IDs are model-local. Browser position is restored by byte names. This simpler design retains old+replacement+compacted data during rebuilding and costs extra peak memory; repeated refresh evidence reports that cost explicitly. An initial stat/open failure leaves the old model intact. Refresh supports cancellation and UI polling.
- Built-in deletion is no-follow, descriptor-relative, limited to scanned children, default-No, and abortable with partial failure reporting. Confirmed unlinking updates surviving nlink observations; post-action refresh obtains current metadata. A custom command's target is gone only on ENOENT, never on arbitrary stat failure. Its quoted path argument/environment and shell tty transitions are tested on owned temporary trees.
- libc provides ABI types, zstd with default features disabled provides bundled Zstandard 1.5.7, unicode-width measures columns, and unicode-segmentation preserves graphemes. Cargo.lock pins dependencies/native tooling. Primary crate APIs and Linux statx/getdents documentation were inspected. Rust links no ncurses; controlled Zig uses system ncurses and Zstandard 1.5.7. Natural sorting is an altered Rust implementation of Martin Pool's algorithm; MIT and upstream natural-sort notices are retained.
- Retain unwind, portable CPU targeting, and a symbol-bearing profiling profile. Ordinary release versus ThinLTO/codegen-unit measurements are separate experiments; compiler flags and artifact hashes accompany each result. Distribution stripping is independent of model memory. No native-target/PGO/allocator/static-musl advantage is hidden in primary comparisons.
- The user's original tree, flags, cache state and RSS units remain unknown. Synthetic results cannot establish the reported 30-second/77-MB performance objective. No cache drops, root commands, remounts or user-tree mutations are used for measurement.
